# Roadmap продукта «МояЗапись»

Целевой сценарий: мастер регистрируется → даёт ссылку/QR → клиент записывается → мастер получает уведомление в **одном** выбранном канале: **MAX** / **VK** / **Telegram** / **email (Mail.ru)**.

Владелец SaaS управляет мастерами, тарифами и доступными сервисами через **админ-панель**.

## Модель уведомлений (целевая)

```
Мастер подключает каналы (MAX bot / VK bot / email)
        ↓
Выбран ровно ОДИН активный канал (свитчер)
        ↓
Запись → outbox → только этот канал
```

| Канал | Как подключается | Кто может выбрать |
|-------|------------------|-------------------|
| MAX | `/connect` в боте | мастер + админ |
| VK | Callback / connect-код | мастер + админ |
| Telegram | `/connect` в боте (VPN ок) | мастер + админ |
| Email | адрес (часто @mail.ru) + SMTP платформы | мастер + админ |

Админ позже сможет **ограничивать** доступные каналы по тарифу (например, email только на Pro).

### Фаза 4 — контроль SaaS (новый блок)
Раньше в роадмапе были только «тарифы» без операционки. Добавляем:

#### 4.1 Админ-панель (F29)
- Вход по `ADMIN_SETUP_KEY` (S0) → позже отдельный admin user  
- Список мастеров: статус, канал уведомлений, подписка, дата оплаты  
- Карточка мастера: включить/выключить сервисы (feature flags), сменить канал, заблокировать  
- Первые «сервисы» в админке: выбор системы оповещения, доступ к публичной записи

#### 4.2 Подписки вручную (F30)
Без эквайринга на старте:
- `plan`: `trial` \| `basic` \| `pro`  
- `subscription_status`: `trial` \| `active` \| `past_due` \| `blocked`  
- `paid_until`  
- Админ продлевает/блокирует; при `blocked` — публичная запись и notify off  
- **F34**: авто-напоминание владельцу на email об истекающих подписках (cron)

#### 4.3 Онлайн-оплата (F31, позже)
ЮKassa / CloudPayments → автопродление `paid_until`.

### Фаза 5
Салон (несколько мастеров), каталог, white-label.

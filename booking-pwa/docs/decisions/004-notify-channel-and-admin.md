# ADR 004 — Один канал уведомлений + админка SaaS

## Статус

Accepted

## Контекст

Сейчас новая запись ставит outbox и в MAX, и в VK (если оба ID заданы). В РФ у мастеров обычно один привычный мессенджер или почта Mail.ru. Параллельная доставка шумная и усложняет поддержку.

Нужен контроль владельца продукта: кто пользуется сервисом, какой тариф оплачен, какие функции включены (начиная с канала оповещений).

## Решение

1. У мастера ровно один активный канал: `masters.notify_channel` ∈ `{ max, vk, telegram, email }`.
2. Подключения каналов независимы (`max_user_id`, `vk_user_id`, `telegram_user_id`, `notify_email`); доставка идёт только в выбранный.
3. Email — через платформенный SMTP (типично Mail.ru), не клиентский SMTP мастера.
4. Админ-панель (`/admin`, F29) — источник истины для подписок и feature flags; мастерский свитчер работает в рамках разрешённого тарифом.
5. Telegram разрешён как опциональный канал (ADR 005); MAX/VK остаются приоритетом для РФ без VPN.

## Последствия

- Outbox: enqueue одного канала (+ reminder в том же).
- Нужны env SMTP для F28.
- Админка S0: защита `ADMIN_SETUP_KEY` / cron-ключом; отдельные admin-аккаунты — позже.
- Тарифы сначала ручные (F30), эквайринг — F31.
